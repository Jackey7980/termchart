# 边界与限制：不可信输入怎么处理

容错解析（`io` / `data`）与 AutoViz 共用一条原则：**宁可如实说"这条没看懂"，也不猜一个看起来合理的结果**。
猜错的代价远大于丢一行——把张三的金额记到李四名下、把 15% 记成 15 元、把 `1740787260` 记成 2025 年，这些错误都不会自己喊疼。

本文只写**已知边界**，每条都有代码落点与回归测试。能力清单见 [reference/capability_matrix.md](reference/capability_matrix.md)，未做项见 [reference/backlog.md](reference/backlog.md)。

## JSON / JSONL 的位置式数组行

JSONL 里常见两种行：对象（带 key）与数组（纯位置，无列名）。

- **对象行**：按 key 展开，`loc.lat` 这类嵌套展平成点路径。
- **对象数组**（`[{...},{...}]`）：逐个对象展开成多行，不参与位置对齐。
- **标量数组**（`["X004", 1740787200, "(123.45)", ...]`）：**仅当元素个数严格等于当前列数**才按列序 zip 成一行；否则整行丢弃。

为什么不做"补齐空值"或"按类型猜列"：宽度不符说明这行根本不是这张表的行（多半是另一份导出、或汇总行），硬对齐等于编造。列序以**首个对象行的 key 出现顺序**为准，每遇到新 key 追加到末尾（新列表头补 `Empty`）。

可观测计数（`data::parse_dataframe_json` → `JsonFrameResult`）：

| 字段 | 含义 |
| --- | --- |
| `lines_total` | 读到的非空行数 |
| `lines_used` | 成功成行的行数（**含** zip 回来的数组行） |
| `lines_zipped` | 其中靠位置 zip 救回的数组行数 |
| `lines_skipped` | 丢弃的行数（宽度不符、首行即数组、非标量非对象、坏 JSON…） |

**残余风险（刻意接受）**：宽度恰好等于列数、但**列序与对象行不同**的导出文件，会被按位置错放。这类错位不会静默：错进时间列的字符串会让该行时间解析失败，从而出现在[下面的告警](#时间格式族与刻度)里（`有 N 行时间无法解析（"X003"），已跳过`）。跨表混流的输入请先统一成对象行再喂进来。

## 百分比与纯数值同列（量纲冲突）

`15%` 的数值是 `0.15`，**不能**和 `1234.5` 元的金额一起求均值——两者差四个数量级，几个百分点就能把整段均值拽向 0，读者会以为"这段时间没交易"。

- `CellFlag::Percent` 在**两条解析轨都打**：CSV 与 JSON 共用 `detail::map_scalar_flags`，同一份数据不会因为入口不同得出两套结论。
- `ColumnProfile::percent_cells` 计数；`mixed_units` 表示**部分格是百分比**。整列都是百分比（`0.15 / 0.32 / …`）不算冲突——那只是比例列，自洽。
- 命中 `mixed_units` 时：百分比格**按缺失处理**，折线在该点断开、柱状图该桶没有柱子，并在告警里说明个数：
  `有 N 个百分比单元格与纯数值同列（量纲不一致），已按缺失处理，未做任何换算`。
- **绝不乘 100**：那是把 15% 伪造成 15 元。要参与金额计算，请在源数据里换算后重新导入。
- 这些格**不参与**离群值扫描，也**不计入**空值率惩罚——它们不是"极小值"也不是"缺失"，是"另一个量纲"。两边各罚一次会让图表类型都被一个格子改写（折线解析分被压 0.05，输给事件柱状图）。

## epoch 数字串（`1740787260`）

**不识别**。`parse_timestamp` 只吃 ISO 家族（见下节），纯数字串一律当"不是时间"。

原因：一个 10 位整数与订单号、金额、自增 ID 在字面上不可区分。猜"10 位即秒级时间戳"会把 `1740787260` 解释成 2025-03-01，于是 2026 年的时间轴里凭空多出一个错年的点——比跳过它糟得多。

- 后果：该行没有 `x`，折线少一个点，并留痕：
  `有 N 行时间无法解析（"1740787260"），已跳过；X 轴只覆盖可解析的时间段`。
- 确需画 epoch：导入前转成 ISO（或在 pandas / SQL 里先 `to_timestamp`）。库里没有"猜时间戳单位"的开关，也不打算加——猜错一次就是错年。

## 时间格式族与刻度

形状扫描的真源是 `data::split_timestamp_shape`，历法校验与 epoch 换算在 `autoviz::parse_timestamp`。

- 年**严格 4 位**；日期分隔符 `-` `/` `.` `年` `月` 可混用；月/日 1–2 位不补零（最短 `2026-1-1`）。
- 日期与时间之间：`T`、空格、`日`；时分秒用 `:`；可用 `Z` 或 `±HH:MM` 标时区。
- 时区偏移**生效**（`epoch -= offset`，上限 ±23:59）；无偏移的字符串按 **naive UTC** 解释。不做本地时区推断——否则同一份数据在不同机器上会画出不同的图。
- 历法校验严格：`2026/13/40` 形状合法但历法非法，直接拒；合法域 `1400 ≤ year ≤ 9999`，闰年按公历（`second ≤ 60` 容忍闰秒）。
- X 刻度按**日历对齐**：步长取 `nice_bucket_seconds` 的 1-2-5 阶梯（1 秒 → 1 年），起点 `floor(tmin / step) * step`，因此刻度落在整 12 小时 / 整日 / 整月，既不会出现 `50000s` 这类"假精度"间隔，也不会把轴撑到数据范围之外的日子。

## 极值裁剪的两道闸

样本少于 10 个、或越界占比超过 20% 时**不裁轴**，退回 `[min, max]`（判据与理由见 [guide/autoviz.md](guide/autoviz.md)）。域外点被钳到轴边缘，仍画在图上——裁剪不是洗数据。

播报口径**只有一个**：`ChartCandidate::final_clip_desc` 由路由用全量值算出，图题后缀与 `WARN` 逐字同源；`final_clip_count()` 给出真正的裁剪点数（没裁就是 `0`）。调用方不需要、也不应该自己拿 `features.outliers` 的抽样结论去猜"到底裁没裁"。
