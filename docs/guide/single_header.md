# 单头用法与代价

## 是什么

`single_include/` 下的聚合头把 `include/termchart/**` 合成单个文件，
复制进项目即可用，不要求跑构建系统生成源码清单。

**它是生成物，禁手改**——由脚本从 include 树产出，改动必须回源头（各模块头）
再重新生成。

## 用法

```cpp
#include "termchart_single.hpp"   // 以 single_include/ 实际文件名为准
```

## 代价

| 方面 | 影响 |
| --- | --- |
| 编译时间 | 单个 TU 承载全部模块，改任何一处头都触发整体重编 |
| 增量构建 | 无——源码级模块边界（include/ + src/ 同名 cpp）被抹平 |
| 裁剪 | 最小构建（TERMCHART_MINIMAL_BUILD）不可用，全部模块进来 |
| 符号 | 全部在一个 TU 内，内部链接优化机会与多 TU 构建不同 |

## 建议

- 快速评估/教学/单文件示例：单头合适；
- 真实项目：走源码并入或 CMake 子目录（installation.md），享受按模块裁剪
  与增量编译；
- 两者混用会导致 ODR 风险：同一二进制内只用一种方式。

## 验证

聚合头本身纳入生成物一致性校验（`check_generated`）；
`tools/` 下的生成脚本为唯一更新通道。
